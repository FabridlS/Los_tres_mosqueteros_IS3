# Título: ADR-001 Elección del Stack de Base de Datos y ORM (PostgreSQL + Prisma)

**Estado:** Aceptado 

**Fecha:** 2026-04-15

**Decisores:** DA ROSA Jesica M., de LOS SANTOS Fabrizzio R., GRABOVIESKI Matias A.

**Relacionado:** project.md

**Contexto**
- Qué problema se está resolviendo: Necesidad de un motor de persistencia de datos relacional para gestionar eventos, usuarios, inscripciones y acreditaciones de forma íntegra. 
- Qué restricciones aplican (negocio, técnica, legal): El entorno de desarrollo backend utiliza Node.js 20+ y TypeScript 5+. Se requiere una solución con soporte nativo de tipos. 
- Qué datos de proyecto sustentan la decisión: El modelo de datos presenta múltiples relaciones estructuradas (ej. un Evento tiene múltiples Sesiones e Inscripciones, y estas últimas determinan Certificados). 

**Decisión**
Qué se decide exactamente: Utilizar PostgreSQL (versión 15+) como motor de base de datos relacional y Prisma ORM (versión 5+) para el modelado y acceso a datos.
- Alcance (qué cubre y qué no cubre): Cubre la capa de persistencia principal. No cubre el almacenamiento de archivos (los PDFs de certificados se almacenan en el sistema de archivos del servidor). 

**Alternativas consideradas**
- Opción A (MongoDB + Mongoose): 

    Pros: Flexibilidad de esquemas, rápido desarrollo inicial. 

    Contras: No es relacional por naturaleza, lo que dificulta mantener la consistencia en transacciones complejas como las inscripciones con cupos máximos.
- Opción B (MySQL + TypeORM): 

    Pros: Relacional y maduro. 
    
    Contras: TypeORM tiene una curva de aprendizaje mayor y la sincronización de tipos con TypeScript no es tan fluida como la autogeneración de Prisma.

**Consecuencias**
- Beneficios esperados: Tipado estricto extremo a extremo (Type Safety) previniendo errores en tiempo de ejecución, y migraciones de esquema fáciles de manejar con `prisma migrate`.
- Costos o riesgos que se aceptan: Prisma tiene una sobrecarga de rendimiento ("overhead") comparado con consultas SQL nativas directas.
- Impacto en operación y equipo: Todo el equipo debe familiarizarse con la sintaxis del `schema.prisma`.

**Plan de implementación**
- Pasos mínimos para ejecutarla: Configurar `DATABASE_URL` en `.env`, crear los modelos en `schema.prisma` y ejecutar `npx prisma db push` / `npx prisma migrate dev`.

**Dependencias**
- Node.js, entorno local de PostgreSQL.

**Métrica de éxito**
- Capacidad de consultar y persistir relaciones complejas entre Eventos y Usuarios con 0 errores de tipado en TypeScript.

**Triggers de revisión**
- Qué condiciones obligan a reabrir esta ADR: Si las consultas a través de Prisma presentan cuellos de botella de rendimiento severos ("N+1 query problem") que no se puedan optimizar.
- Fecha sugerida de revisión: 2026-11-01.
