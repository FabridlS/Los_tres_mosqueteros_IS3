# Título: ADR-003 Selección del Lenguaje y Framework para el Backend

**Estado:** Propuesto

**Fecha:** 2026-06-16

**Decisores:** DA ROSA Jesica M., de LOS SANTOS Fabrizzio R., GRABOVIESKI Matias A.

**Relacionado:** project.md

**Contexto**

- Qué problema se está resolviendo: Se debe definir la pila tecnológica base (lenguaje y framework) para el desarrollo del backend del sistema antes de comenzar la implementación de los distintos specs del proyecto.


- Qué restricciones aplican (negocio, técnica, legal): El proyecto es de índole académica universitaria. Se requiere un lenguaje fuertemente tipado que soporte programación orientada a objetos, inyección de dependencias y facilite el desarrollo de una API RESTful estructurada.


- Qué datos de proyecto sustentan la decisión: El equipo cuenta con conocimientos y experiencia previa desarrollando aplicaciones y consumiendo bases de datos relacionales en entornos .NET.

**Decisión**

- Qué se decide exactamente: Se decide utilizar C# junto con el framework .NET para la construcción de los servicios backend y las APIs.
- Alcance (qué cubre y qué no cubre): Esta decisión cubre exclusivamente la lógica de servidor, controladores, acceso a datos y enrutamiento del backend descrito en el project.md. No cubre el desarrollo de las interfaces de usuario (frontend).



**Alternativas consideradas**

- Opción A (C# con .NET):
- Pros: Excelente rendimiento, fuerte tipado que reduce errores en tiempo de ejecución, ecosistema maduro, integración nativa con SQL Server y familiaridad técnica del equipo.
- Contras: Puede requerir configuraciones más detalladas en el manejo inicial del entorno y dependencias.


- Opción B (Node.js con Express):
- Pros: Alta velocidad para generar prototipos, uso de JavaScript en todo el stack.
- Contras: Tipado dinámico por defecto, lo que puede aumentar la propensión a errores a medida que el sistema crezca (salvo que se incluya TypeScript).


- Opción C (Java con Spring Boot):
- Pros: Arquitectura extremadamente robusta y escalable para nivel empresarial.
- Contras: Mayor verbosidad en el código y una curva de aprendizaje más pronunciada para la configuración inicial.



**Consecuencias**

- Beneficios esperados: Mayor mantenibilidad del código a largo plazo, seguridad en el manejo de tipos y agilidad en el desarrollo gracias a las herramientas de Visual Studio/C#.
- Costos o riesgos que se aceptan: Dependencia técnica del ecosistema de Microsoft y su ciclo de vida de versiones.
- Impacto en operación y equipo: El equipo de desarrollo deberá estandarizar sus entornos de trabajo utilizando el SDK de .NET y gestionar las librerías necesarias mediante el gestor de paquetes NuGet.

**Plan de implementación**

- Pasos mínimos para ejecutarla: Instalar el SDK correspondiente, inicializar la estructura del proyecto web API, configurar el entorno de desarrollo y crear un controlador de prueba para confirmar la operatividad.

**Dependencias**

- SDK de .NET instalado en los equipos y en el entorno de despliegue.

**Métrica de éxito**

- La API base compila sin errores y el endpoint de prueba responde con código HTTP 200 en un tiempo menor a 200ms en el entorno local.

**Triggers de revisión**

- Qué condiciones obligan a reabrir esta ADR: Incompatibilidad insalvable con alguna librería externa crítica para el negocio, o requerimientos del servidor de producción que no soporten .NET.
- Fecha sugerida de revisión: 2026-12-16
